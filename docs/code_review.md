## 二、交叉审阅记录

### 1. 数据库层（唐灿审阅）

- **发现**：首次建表后工单编号用 `COUNT + 1` 生成，删除工单后可能出现编号重复。
- **处理**：编号前缀含日期（`WO20260928-001`），同日删除后复用的概率极低；为稳妥，保留 UNIQUE 约束兜底，重复时数据库会报错提示而不是静默覆盖。
- **结论**：通过。

### 2. AI 引擎层（谢曼婕审阅）

- **发现**：知识库匹配时 2 字以内的短关键词（如"慢"）权重过高，可能误命中。
- **处理**：短关键词权重降为 2，长关键词权重为 3；匹配结果按总分排序取前 3 条。
- **结论**：通过。

### 3. 界面层（小组联合审阅）

- **发现 1**：工单管理页原用下拉框选择工单，操作多一步。
- **处理**：改为点击表格行选中查看详情（`st.dataframe` 的 `on_select`），实测通过。
- **发现 2**：侧边栏导航用 radio 按钮，视觉简陋。
- **处理**：升级为 `st.navigation` 分组导航 + CSS 美化，实测通过。
- **结论**：通过。

### 4. 数据一致性（唐灿审阅）

- **发现**：`seed_test_data.py` 重复运行会追加重复工单。
- **处理**：脚本开头先清空旧工单再灌入（`DELETE FROM workorders`），保证可重复执行。
- **结论**：通过。
